# IPC at 81 MHz: the next three goals

Kind: plan, 2026-11-05. Applies to the canon `fprisc-81` (core 187c637),
which measures **IPC 0.380, 30.8 MIPS** on the board (512/128 classifier,
126 runs, `mcycle`/`minstret`). Follows [LOAD-USE](2026-11-05-LOAD-USE.md)
and [SDRAM-CLOCK-DECISION](2026-11-05-SDRAM-CLOCK-DECISION.md).

Where classifier cycles go (simulation, 48/48, after shifts in E1): 41% issue,
14.0% front end empty for other reasons, 9.9% stalled behind a load in M,
9.2% cache misses, 8.5% branch restarts and refill, 5.9% waiting on a plain
ALU result in E1, the rest smaller.

## 1. Make the design placeable (floorplanning)

The chip is ~85% full and at the edge of routability: one extra mux input
(L1) moved placement 1 from 82.65 to 62.7 MHz with every failing path in
untouched logic, and the three-clock cache port (L2, 1.106x) only fails
because the core must sit beside the cache without the return register.

Goal: a region constraint (`SDRAM_REGION_CST`) that keeps the cache and the
core's memory-facing stages (E2, M, fetch) together, such that:

- the canon still closes 81 MHz with at least its current +0.247 ns, at
  more than one placement option (today only placement 1 is known good);
- L2 closes 81 MHz with margin, and then passes the RTL checks, the board
  processor checks and the FP-RISC suite;
- target: IPC about 0.42 on the board (L2's 1.106x on 0.380).

## 2. Split the "front end empty, other" bucket (14%)

The largest stall share is not yet attributed. Add observation counters
(behind `PIPELINE_SLOT_OBSERVATIONS`, no effect on the board image) that
split it into: fetch waiting for the shared port (loads and stores own it;
"fetch port blocked" covers 16.4M cycles), RVC halfword assembly bubbles,
assembly-stage JAL/return steers, and queue underflow after a BTB-predicted
jump.

Goal: every cycle of the 14% assigned to one cause, summing exactly like
the existing split; then price the largest cause in simulation. If port
contention dominates, a dedicated fetch path (dual-ported BSRAM reads or a
small instruction buffer) becomes the next structural change.

## 3. Prediction and the cache (smaller, area-bound)

- Branches: 796K taken branches the BTB missed and 314K false "taken"
  predictions. A larger BTB lengthens the BTB loop (the 81 MHz limiter
  before shifts), and 2-bit counters priced small; revisit after 1, when
  placement has room.
- Cache misses: 9.2% at 48/48, about 15% at 81/48. BSRAM is 40 of 46
  used, so a larger cache is not available; next-line prefetch on code
  refills is the candidate to price.

Goal: price both in simulation only after 1 and 2, and build only what
beats 1.03x in clock x IPC.

## Expectation

With 1 working, IPC about 0.45-0.50 at 81 MHz looks reachable (L2 plus part
of the front-end bucket). Beyond that, IPC gains start to cost clock.
