# Pin 76: one image for the servo and the transistor motor, driven from FP-RISC

Kind: peripheral change, timing and board record, 2026-11-23. Follows
[SERVO-TIMING](2026-11-22-SERVO-TIMING.md).

## Result

The transistor motor test (qos `hal/spectre/actors/motor/`, NPN low-side
switch on package pin 76) no longer needs its own bitstream. Its image used
`motor_gpio.v` in place of `servo_pwm.v` and missed 84 MHz by 0.551 ns. That
image was built outside this repo. `servo_pwm.v` now has a level mode instead.
The `SDRAM_SERVO=1` fprisc-84 image serves both loads, and software decides
which one the pin drives:

| Word written to 0x10001010 | Pin 76 |
|---|---|
| 1000-2000 | servo PWM, that many µs high per 20 ms frame, from the next frame |
| 1 | high at once (motor on); PWM off from the next frame |
| 0 | low at once (motor off); PWM off from the next frame, a pulse in progress finishes |
| anything else | ignored |

The hardware only holds the word. Everything else lives in FP-RISC: the
on/off timing, how many pairs, which servo positions and how long each is
held. That code is fprisc `std/tangnano20k/pin76.fpr`, with
`examples/tangnano20k_motor.fpr` and `examples/tangnano20k_servo.fpr`. The
one piece of C is `machine/tangnano20k/pin76_hal.c`, a single checked
register store.

The core is unchanged: its Verilog is the same as the servo image of
[SERVO-TIMING](2026-11-22-SERVO-TIMING.md). Only the block outside it
changed.

| Image | p0 | p1 (= p2) | p3 (preset) | p4 | Passes |
|---|---:|---:|---:|---:|---:|
| motor_gpio, external build | | | −0.551 | | fails |
| servo only (`6abaea1` logic) | −0.397 | +0.017 | +0.050 | +0.152 | 3 of 4 |
| **servo + level, this change** | **+0.259** | **+0.141** | **+0.011** | **+0.035** | **4 of 4** |

At p3 the image runs at 84.076 MHz with 13,218 logic and 8,079 CLS. Every
placement option closes, which the servo-only netlist did not. The p3 margin
is thin, as on every non-canon netlist on this part
([timing.txt](evidence/2026-11-23-pin76-motor/timing.txt)).

## Checks

- `servo_pwm_tb.v` adds level cases: 1 is immediate and holds a whole frame,
  0 is immediate, high bits are ignored, a PWM write after a level drops the
  level, and 0 never cuts a pulse short. The new module passes. The previous
  module fails the level cases.
- Board, pin-76 image in FPGA SRAM, ROM build id `1117eb6fa223746e`:
  - processor check passes, plus 7,680 RV32M and 11,520 RV32I checks at 84 MHz
  - FP-RISC motor program: 15 pairs of one second on and one second off,
    ending with the output off ([log](evidence/2026-11-23-pin76-motor/fprisc-motor-board.log))
  - FP-RISC servo program: 1500, 1400, 1600 and 1500 µs, then off
    ([log](evidence/2026-11-23-pin76-motor/fprisc-servo-board.log))

  The board was then reconfigured from flash.
- Not observed: no motor or servo was watched, and no probe was on pin 76.
  The runs prove the stores reach the register without a fault and the
  programs complete. Movement still needs someone at the bench with the
  wiring in qos `motor/wiring.md`.

## Open

- p3 margin +0.011 ns. If the next netlist change loses p3, the evidence here
  favours p0 (+0.259) for this image over re-spelling logic.
- A stock image faults on the pin-76 store. There is still no capability word
  software can probe: offset 12 must stay `SDP1`, because fprisc's
  `sd_hal.c` checks it exactly.
