# A 64-entry BTB in block RAM

Kind: core change, simulation and timing builds, 2026-10-30. Follows
[RETURN-STACK-AND-STRADDLE](2026-10-30-RETURN-STACK-AND-STRADDLE.md), the
third fix ranked in [STALL-SPLIT](2026-10-30-STALL-SPLIT.md). No board run.

## Result

On the frozen classifier at 48/48 MHz, going from 8 to 64 BTB entries cuts
cycles by **1.069x** (IPC 0.320 to 0.342). Against the core before this
session's predictor work, the total is **1.260x**. The classifier output is
correct (train 124/128 digest 21562, test 61/64 digest 909572).

The design passes timing at 60 MHz (placer aimed at 66 MHz) at all three
placements. It uses 424 more LUTs and 269 fewer registers than the 8-entry
version, plus two block RAMs.

| Design | 60 MHz builds (placements 0 / 2 / 3) | Worst Fmax | IPC | Fmax x IPC |
|---|---|---:|---:|---:|
| Before the predictor work | pass 75.2 / 71.6 / 61.4 | 61.4 | 0.272 | 16.7 |
| 4-entry return stack, 8-entry BTB (c5df482) | pass 63.0 / 75.5 / 67.4 | 63.0 | 0.320 | 20.2 |
| + 64-entry BTB | pass 64.2 / 63.0 / 61.6 | 61.6 | 0.342 | 21.1 (1.26x) |

## What changed

- 64 entries, indexed by pc bits 7..2, tagged with bits 15..8 (was 8 entries,
  bits 4..2 and 12..5).
- `SdramPipeline.btbStorage` keeps slot, tag and target in a 64 x 41
  asynchronously read RAM, read at the registered fetch pc's index. Valid bits
  stay in 64 flip-flops so reset clears them; an invalid entry's other fields
  are never inspected.
- The core reads one entry: the stored one, or the pending write's if it is
  for the fetch index. The board feeds that one entry into every slot of
  `pBtb`, so no 64-way mux is built.
- Tests: the straddle-alias test plants a foreign entry, because aliases are
  now 64 KiB apart, beyond the simulated RAM. The storage hold test compares
  the entry read at a random index.

## Simulation

| Version | Cycles | E2 redirects | Front redirects |
|---|---:|---:|---:|
| 8-entry BTB | 123,432,187 | 2,108,351 | 2,916,450 |
| 64-entry BTB | 115,446,617 | 1,496,193 | 1,932,168 |

Taken branches without a prediction fell from 1.80M to 1.19M; not-taken
mispredictions rose from 207K to 302K (more aliased "taken" entries). The
replay model predicted 1.44M branch redirects; the core shows 1.49M.

## How synthesis built it

Gowin did not use distributed RAM. It put the table in two block RAMs (SDPB)
and absorbed the fetch pc's index bits into the block RAM's read-address
register. It kept the hold: the address is built as "hold ? current fetch pc
: next fetch pc", reset included.

Two consequences:

- **The critical path moved.** At placements 2 and 3 the worst path runs from
  the pending write's index through the bypass compare and the hit decision to
  the next fetch pc, which is now the block RAM's read address. It still
  passes 60 MHz everywhere.
- **Read during write.** If the table is written and read at the same index
  on the same clock, the block RAM may return the old entry for one cycle.
  That can only cost one prediction (E2 checks every one), and the RTL
  simulation does not model it, so the board may run a few cycles slower than
  simulated.

## Open

- Not run on the board; a gate-level simulation (`run_gls.py`) would confirm
  the block-RAM mapping.
- 128 entries: the model gives another 0.39M branch and 0.31M JAL redirects
  fewer. The table would still fit in two block RAMs; the tag would lose a bit
  or the RAM would grow.
- Not-taken mispredictions grew; a direction bit (2-bit counter) per entry
  would address them, and the model priced that as small at 64 entries.
