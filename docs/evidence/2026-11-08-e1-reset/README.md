# E1 payload reset experiment

The hardware change is `e1-reset.patch`. The new reusable RTL comparison is
`boards/tangnano20k/sdram/check_pipeline_reset.py` with `pipeline_reset_tb.v`.
Both tests use fresh observed RTL; synthesis uses the separate production top.

Run from the repository root, with generated RTL in
`output/refactor-e1-2026-11-08/`:

```sh
python3 boards/tangnano20k/sdram/check_pipeline_reset.py \
  --baseline output/refactor-e1-2026-11-08/baseline-observed/SdramPipelineObserved.topEntity/sdram_pipeline_risc.v \
  --candidate output/refactor-e1-2026-11-08/candidate-generated/SdramPipelineObserved.topEntity/sdram_pipeline_risc.v \
  --out output/refactor-e1-2026-11-08/reset-check
python3 boards/tangnano20k/sdram/check_pipeline_rtl.py \
  --generated output/refactor-e1-2026-11-08/candidate-generated/SdramPipelineObserved.topEntity \
  --out output/refactor-e1-2026-11-08/rtl-check \
  --compressed --simulator verilator --cache-ways 2 --cache-line-bits 11 --cdc-bridge
```

`measure.py`, `route.py` and `route-p0.py` are the executed physical drivers.
They retain the previous experiment's fixed stamped ROM and the same clock,
map, route and floorplan settings. Physical outputs and large netlists remain
under `output/`; reports, configuration and hashes are saved here. Gowin needs
network licence access; synthesis retries only licence failures.

The baseline physical directories in this experiment are links to the frozen
`output/refactor-2026-11-07/baseline-*` results. Their archived evidence is in
`../2026-11-07-refactor/physical/`. Baseline netlist, RTL and ROM hashes were
verified before reuse. Fresh baseline production RTL is byte-identical to its
frozen counterpart. Generated RTL uses `-DRISCV_COMPRESSED`, `-fclash-clear`,
`-isrc` and `-hide-package simple-risc` with the same local Clash executable.

The baseline/candidate comparison uses a small deterministic stream, pseudo-
random holds and 20 completed reset/restart episodes. It is a targeted
regression, not exhaustive proof. An ignored-warm-reset negative control must
fail at epoch 1; its expected fatal log is not a failed positive test.

`fanout.py` counts direct synthesized core pin loads, excluding constants and
clocks. The E1 group attribution includes its validity bit. Vendor high-fanout
reports cover the whole routed design and therefore have different totals.
`physical-summary.json` comes from `summarize.py`; routing averages cover the
25 setup paths emitted by the tool, not all possible paths.

Bitstreams generated by these drivers are experiments with a fixed ROM
identity. Do not use them as correctly stamped releases or as board adoption
evidence. No board was programmed by this experiment.


A second control regenerates the current working tree with only E1 reset
restored. It is identical to the frozen production RTL after removing source-
location comments (the unused division helper shifts source line numbers).
`control-verification.json` records raw and normalized hashes. No logic or
signal naming changes come from retaining that helper.


Placement 0 was started concurrently while placement 3 was still routing.
`route-p0.py` uses `p0.started` to suppress the previously queued duplicate;
remove that guard file only when intentionally rerunning the experiment.
Elapsed run times include overlapping work and licence/report overhead.


Final result: both placements fail the 81 MHz setup gate. The default source
has been restored to `regEn`; reapply `e1-reset.patch` before regenerating the
measured candidate. `git apply --check` verifies that patch against the final
tree. The new test tool and testbench remain in the repository. See the dated
report for the decision and the distinction between fanout and timing results.
